# Leaderboard and About redesign

This source implements the November 2 approved Paper brief in Pirate Design System, file 01M4DWHDEJ6WVWRH6FVX7E3017. The reference sheets are Screens/Community/CommunityPage, Screens/Rewards/Leaderboard, Parts/Rewards/Streak and Screens/Songs/YourSongs. Paper JSX exports supplied the 390px phone, 1280px desktop, 56px header/list rows, 20px card padding, 24px join-rule slot, 20px icons, 72/56px podium avatars, 100/72/56px podium bases, warning counts and neutral surface tokens. Desktop visitor/empty/loading/error behavior follows the caption. Those states now have executable stories at explicit phone and desktop widths.

The community shell renders a single activity preview inside About before Rules, including in its desktop aside. It has no slot above the tabs. The handle joins the membership counts in the header. The public preview's membership gate summaries supply the country allowlist. Simple supported policies get the open, Palm or nationality row; complex, unknown or exclusion-based policies retain an honest requirements message. Request-based policy offers neither unsupported request controls nor the old membership-request copy. This changes no backend policy.

Community activity opens at /c/:path_segment/leaderboard. Song activity opens at /posts/:slug/leaderboard, with /post/:postId/leaderboard resolving through the existing API-owned canonical song lookup. These are streak rankings; the Karaoke best-score route remains separate. The About return link retains tab=about. Optional return destinations accept only bounded local paths. Canonical post origin and locale reuse the existing post route helpers.

The full page keeps server ordering and rank labels. The podium contains the first three entries, and the list continues by position; 1,2,3,3,5 retains the fourth entry at rank 3. Private progress supplies week marks, current/best/total and standing. Neither the browser date nor an array index invents a qualification or rank. Anonymous SSR remains a deterministic loading shell with no private reads. Public board and private-read failures remain independent. The viewer's actual row controls its noninteractive pinned visual copy through intersection observation; the copy stays aligned to the board column on resize and hidden from assistive technology.

Presenting-profile commands and qualifying requirements remain in a lower section of the full page. The existing controller still owns community/account fencing, CSRF, idempotent uncertain-command retry, aborts, readback and session changes. The preview mounts no profile or requirements controls. Song posts retain their existing inline board and gain See all. The Error presentation avoids promising an unconfirmed private streak is safe. Empty reads invite Study or singing only; Dance is not an enabled streak producer.

Your Songs has an unreleased song-library endpoint in the existing application. Its component now accepts server-supplied currentStreak and leaderboardPath, displays number-then-flame counts, and offers the leaderboard from the song detail sheet. Stories exercise these supplied-data states. Production still renders the existing not-yet-available library state until that API is released and vendored; this change does not invent fixture songs or a history endpoint.
